# Deployment and operations boundary

The repository provides a local development stack and a **reference hosted overlay**, not an approved public-service deployment. It does not establish the security, data protection, legal, performance or accessibility of an operated financial service. Do not copy disposable local credentials or expose the root Compose stack directly to the internet. Any deployment needs an operator, a threat model and a review specific to its target. See [local setup](local-setup.md), [testing](testing.md), and [hosted reference](../../deploy/README.md).

## Local Compose topology

Root [compose.yaml](../../compose.yaml) defines PostgreSQL 17 (`postgres`, default service), Java API (`backend`, `app` profile) and nginx/SPA (`web`, `app` profile). PostgreSQL publishes `127.0.0.1:${DB_PORT:-5432}:5432`, backend publishes `127.0.0.1:${SERVER_PORT:-8080}:8080`, and web publishes `127.0.0.1:${WEB_PORT:-8081}:8080`. Backend reaches `postgres:5432`; nginx proxies `/api` and `/actuator` to `backend:8080`. The PostgreSQL named volume persists across normal `down`; `COMPOSE_PROJECT_NAME` overrides the root `name: housesync` to isolate volumes. Choose unused host ports when starting a second stack; these overrides do not change container-network ports.

`make db-up` starts PostgreSQL only; `make app-up` builds/starts the `app` profile and waits for service health; `make down` removes containers/network but retains data. Native Make targets source root `.env` (it replaces inherited values), while Compose interpolates `.env` plus exported shell values. Use [the complete Make/environment contract](local-setup.md#environment-contract) instead of assuming shell exports override native Make variables. PostgreSQL initializes credentials on a new volume only; replacing `.env` does not change existing users. Never use volume-removal flags as routine troubleshooting.

Public GET health probes are `/actuator/health`, `/actuator/health/liveness`, and `/actuator/health/readiness`, with hidden details; readiness includes the database. A healthy nginx root alone does not prove the proxy path: test web → API. Anonymous `/api/auth/me` returns 401 and unsafe requests without CSRF return 403. Local Make/Compose allow insecure cookies **only** for localhost HTTP; HTTPS operation requires `SESSION_COOKIE_SECURE=true` and a reviewed trust boundary. Sessions are PostgreSQL-backed; connected finance and AI are optional and disabled by default. Never bake secrets into image layers or web assets.

## CI topology

The [workflow](../../.github/workflows/ci.yml) runs four jobs on every push and pull request: a full-history Gitleaks secret scan; backend Java 21 `make backend-check` with real PostgreSQL Testcontainers; independent Node 22 web lint/types/format/tests/build; and, after the first two, a Compose build/health/web-to-backend proxy check. The workflow uses disposable environment values and never receives real member data or paid-provider credentials. See [testing](testing.md) for commands.

## Operator-reviewed hosted reference

[`deploy/`](../../deploy/README.md) contains a Caddy TLS overlay, a host environment **template**, and age-encrypted backup/pull examples. Those files illustrate a single-host topology with loopback-only database/backend/web ports and public TCP 80/443. They do not by themselves establish working certificates, firewall policy, alert delivery, recovery, access review, or target suitability. HTTP sign-in is internet-reachable once Caddy is exposed: operator-issued, recipient-bound enrollment is required, but it is not a substitute for a security review. Host-local CLI authority is root/Docker-equivalent and is distinct from household `OWNER` rights. No public registration bypass or HTTP administrator endpoint exists. The [operator CLI and recipient lifecycle](../architecture/identity-api.md#operator-cli-boundary) apply wherever that backend runs.

Before a deployment holds **real** household records, its operator should choose and document an approved audience, host/network topology and budget, retention, numeric RPO/RTO and response owner; review HTTPS and exposure; run two-member plus outsider authenticated browser checks, password recovery/revocation, a realistic populated-data backup restore with ledger reconciliation, a delivered failure alert, an upgrade, and an incident/recovery drill. The [backup runbook](../../deploy/backup/README.md) separates what the scripts do from evidence that an operator has done these things; a local smoke or an empty-schema restore cannot stand in for them. Connected-finance production and paid AI need distinct consent, credentials, provider/live-flow verification, retention and cost decisions; manual finance requires neither.

An Android client and a public production release are not part of this repository. Production readiness would additionally need an agreed privacy/deletion policy, managed least-privilege secrets and data lifecycle, vulnerability and authorization review, real screen-reader/zoom accessibility assessment, measured representative capacity, live-provider verification for enabled services, repeatable deployment/rollback and recovery, monitoring/alerts, and support/incident ownership. Rolling back an image does not undo a Flyway migration or recover deleted rows.
